# Виктория Мартянова — сайт-портфолио

**Виктория Мартянова** — лендинг-портфолио творческого человека: показ работ в рекламе, музыкальных видео, фильмах, театре и искусстве.

Формат сайта: одностраничный лендинг-витрина — герой → разделы работ по направлениям → о Виктории → контакты для связи (кастинг-директора, агентства, режиссёры, продюсеры).

Проект делается в рамках практики бренда Mitja (vibe-coding для малого бизнеса в ЕС).

> **Next.js 16.** Breaking changes относительно предыдущих версий — сверяться с `node_modules/next/dist/docs/`, внимательно читать предупреждения об устаревании.

## Протокол работы агента

В начале каждого нового чата:

1. Прочитай этот `CLAUDE.md` (делается автоматически).
2. Прочитай `MEMORY.md` и релевантные файлы памяти проекта.
3. Открой папку `plans/`, найди файл со статусом `активный` в шапке — это текущий план работы. Следуй ему, не придумывая свой.
4. Если активного плана нет — спроси у Дмитрия, с чего начинать.

При новой задаче:

- Если задача вписывается в активный план — работай в нём.
- Если это другая задача — поставь текущий план в статус `приостановлен`, создай новый план в `plans/`.
- Старые планы не удалять — это история решений.

---

## Правила планов

Любая нетривиальная задача оформляется планом в `plans/`.

1. **Один план = одна задача.** Если план уже есть — работай с ним.
2. **Имя файла:** `YYYY-MM-DD-название-задачи.md`.
3. **Статус в шапке** файла — одно из трёх значений:

| Статус | Значение |
|---|---|
| `активный` | Текущая работа. Только один план может быть активным. |
| `приостановлен` | Отложен, вернёмся позже. |
| `завершён` | Все фазы выполнены. |

4. План делится на **фазы**. У каждой фазы чекбокс `[ ]` или `[x]`.
5. В конце плана — итоговый блок: реализован целиком или нет, что осталось.
6. Агент **обязан** актуализировать план после каждой сессии.

## О проекте

### Кто такая Виктория
Художник арт-департамента в кино и рекламе. Работает как costume designer / wardrobe на сетах, делает set design, props, production design, ставит собственные постановки, снимает рекламу, решает разные творческие задачи на площадке.

### Что делает сайт
Публичный портфолио-сайт — витрина работ. Главная задача: показать диапазон и масштаб работ (их **очень много**) и дать удобный способ связаться.

### Для кого сайт
Кинопродакшены, режиссёры, рекламные агентства, продюсеры — те, кто нанимает художника / костюмера на проект.

### Возможные разделы работ (по направлениям)
- **Film** — арт-департамент, кино
- **Advertising / commercials** — реклама
- **Costume / wardrobe** — костюмы
- **Set design / props** — сет-дизайн, реквизит
- **Own productions** — собственные постановки

_(финальная структура и группировка — после разбора рефереса и реальных работ)._

### Язык
Только **английский**. Никакого русского/двуязычия на самом сайте.

### Ключевое требование — самостоятельное редактирование
Виктория должна **сама добавлять и редактировать работы** без разработчика. Решено делать **свою админку** (не Sanity/Payload), но **отложить на Фазу 2**. Порядок работ:
- **Фаза 1** — рабочий сайт, контент наполняем сами.
- **Фаза 2** — своя админка для Виктории.

## Стек

- **Фронтенд:** Next.js 16 (App Router) + React + Tailwind CSS v4 + TypeScript
- **Хостинг:** Railway
- **Репозиторий:** GitHub
- **Видео:** встраивание (YouTube/Vimeo) или хостинг медиа — решить на этапе планирования
- **Контент / админка:** своя админка (Фаза 2). Data-слой — вероятно SQLite/Turso (как в Arina/Alex), чтобы сайт и будущая админка читали/писали одну базу. Картинки: Фаза 1 — `/public`, под загрузку в Фазе 2 — бакет (R2/volume).

## Принципы проекта

1. **Витрина, а не текст.** Сайт продаёт визуалом — работы на первом месте, слов минимум.
2. **Скорость и mobile-first.** Заказчики смотрят с телефона между делом — должно открываться мгновенно и листаться легко.
3. **Не кодить, пока не собран материал.** Без работ и брифа Виктории сайт не наполнить — сначала контент, потом код.
4. **Эстетика = часть продукта.** Для творческого портфолио дизайн так же важен, как функциональность.

## Завершение каждого чата

В конце каждой сессии записывай рефлексию в `история/YYYY-MM-DD-краткое-название.md`.

Формат:

1. Какая задача была поставлена.
2. Как я её решал.
3. Решил ли — да / нет / частично.
4. Эффективно ли решение, что можно было лучше.
5. Как было и как стало.
