# 2026-06-17 — Переделка главной: index-list → grid-first сетка работ

## 1. Задача
Дмитрий забраковал главную в подаче index-first: типографический список работ,
где кадр показывался только по hover/тапу. Экран выглядел пустым, работы не
читались сразу. Цель — переделать блок работ в видимую курируемую СЕТКУ превью
(фото + видео-постеры), как в референсе Ranya El-Refaey («SELECTED WORKS:»):
работы видны за пару секунд, без наведения; фильтры по сетке in-place; mobile —
1 колонка; анти-CLS.

## 2. Как решал
1. Сначала прочитал всю готовую инфраструктуру (план, `Showcase`, `WorkIndex`,
   `page.tsx`, `lib/works.ts`, `schema.ts`, `image.ts`, `VideoEmbed`, манифест C,
   токены `globals.css`) — чтобы переиспользовать, а не переписывать.
2. **Механика featured:** добавил поле `Work.featured` в Zod-схему + `getFeatured(limit=12)`
   в `lib/works.ts` (если ничего не помечено — первые N по `order`). Путь «показать
   все» = существующий `getWorks()`, заложен.
3. **Детект видео без новых данных:** манифест C уже хранит `kind: "image" | "video-poster"`.
   Пробросил `kind` через `ImageMeta` → `RenderableImage` → `IndexEntry`. Видео-плитка =
   `video` ИЛИ `kind==="video-poster"` ИЛИ категория `music-video`.
4. **Новый компонент `WorkGrid.tsx`** (заменил `WorkIndex` в `Showcase`): плитки
   постер+подпись на розовом поле, фильтр по `active` in-place, живая раскладка
   (CSS-грид: 2 крупные сверху `col-span-3` из 6 / 3-в-ряд `col-span-2` / 1 кол. mobile),
   play-маркер на видео, анти-CLS (явный `aspect-ratio`, blur из манифеста, первые 2
   `priority`). При наличии `Work.video` плитка играет inline через готовый `<VideoEmbed>`;
   пока ссылок нет — ведёт на карточку, но с маркером.
5. `Showcase` → `tone="rose"`; About перевёл на `tone="paper"`, чтобы два розовых блока
   не сливались (ритм: hero → marquee → сетка(rose) → About(paper) → Contact(rose-gradient)).
6. Удалил `WorkIndex.tsx` и мёртвый CSS (`.index-row*`, `.floating-preview`, keyframes).
7. `npm run build` — зелёный. Поднял dev, проверил рендер: все 10 кадров на месте,
   3 play-маркера (delta, highsnobiety, tommy-cash), `grid-cols-1` на mobile, 10 ссылок
   на карточки, About — paper.

## 3. Решил ли
**Да.** Сетка рендерит все работы сразу без наведения, фильтры in-place сохранены,
видео и фото в одной сетке, mobile — 1 колонка, билд зелёный, анти-CLS соблюдён.

## 4. Эффективно ли / что лучше
- Эффективно: переиспользовал ВСЮ инфраструктуру (VideoEmbed, манифест, токены,
  примитивы `WorkCaption`/`Section`), добавил лишь поле схемы + один компонент.
- Visual-проверку делал по rendered HTML (срезы grep), не по скриншоту — структурно
  надёжно, но живой скриншот на iPhone/Android остаётся за фазой J (QA).
- Раскладку сделал детерминированной (первые 2 крупные, остальное 3-в-ряд) вместо
  masonry — устойчиво к фильтрации и без CLS; чуть менее «случайная», чем референс,
  но аккуратнее. При желании добавить вариативность — менять только `spanClass()`.

## 5. Как было / как стало
- **Было:** index-list, кадр только по hover/тапу → пустой экран, работы не видны.
- **Стало:** курируемая видимая сетка постеров (фото+видео) на розовом поле,
  «SELECTED WORKS:», play-маркеры, фильтр in-place, 1 колонка на mobile.
